# 原实验室场景的透明器材感知接入方案

日期：2026-10-23。状态：方案已保存，实现待继续。依据：[诊断](LAB_PERCEPTION_GRASPNET_REFACTOR_20261023.md)、[可行性审核与官方来源](LAB_TRANSPARENT_PERCEPTION_FEASIBILITY_20261023.md)、[r2 证据](evidence/transparent-perception-20261023.json)。

## 目标与选定路线

保留用户原有 tabletop_station 场景和玻璃棒入架布局。最终让 Agent 根据实际可读标签选择试剂，经过 GraspNet 抓取、准备和执行，完成倾倒、搅拌、归位，并由现有 Runtime/Coordinator 结算。

**实施主线：全局定位与近景观测 → 标签/实例分割 → ReMake 恢复公制几何 → GraspNet 候选 → 功能点与路线准备 → 执行反馈。** DFNet 只作为同输入对照和可替换 Provider。主线暂不同时集成 ClearGrasp、ASGrasp 或 NeRF，触发条件见后文。

ReMake 已完成本项目真实推理，但当前观测几何未通过执行验证；它的官方 PCF-Grasp 流程不进入 PAOS。近景观测和功能点证据是该方案的一部分，不能只装一个深度模型就认为链路成立。

## 当前问题与修复对应

| 已确认的问题 | 对应改动 | 完成证据 |
|---|---|---|
| 瓶内 mask 的原始深度落到桌面，过滤后主要剩局部标签带 | 实例分割与透明几何恢复分层；保存原始深度、估计深度及支持区域 | 恢复表面与背景分离；几何误差按对象/部位统计 |
| 标签未读出，部分试管误作混合容器 | 补充真实近景，分别校验标签文字和器材类别 | 目标试剂身份唯一；不可读对象保留未确定 |
| 原始相机输入与模型默认裁剪、尺寸不一致 | 显式配置深度单位/范围、缩放、输出尺寸与内参 | 未意外清空有效输入；像素反投影对应正确 |
| 感知对象发布依赖仿真射线绑定 | 先生成感知实体；在准备阶段建立私有执行对应 | 离线图片也能得到感知/候选；绑定失败不能变成执行成功 |
| 标签上沿被当瓶口，可见棒端被当工作端 | 独立过程功能点估计与所需区域检查 | 瓶口/杯口、棒工作端具有各自的观测与几何依据 |
| 抓取前强制要求全部过程功能点，持有后刷新主要更新容器 | 第一版在抓取前收齐任务所需功能点；后续按持有状态更新源工具与容器 | 缺功能点不能进入整套动作；持有后不重新选择抓取候选 |

最后一项来自本轮代码核对：`visual_perception.py` 的 `resolve()` 同时要求 source/destination features；`refresh_process()` 只更新目标容器。原方案中的“先抓再看”不是当前可用能力，不能用空 tool_frame 绕过。

## PAOS 责任与接口

通用层继续拥有目标、实体、候选、准备请求和生命周期；模型 Provider 只估计几何；Isaac Adapter 负责采集、坐标标定和设备/环境执行对应。替换 ReMake、DFNet 或相机时，Agent 指令与公开 Tool 语义保持一致。

在已有感知 Provider 组合边界增加一个可替换的几何恢复接口，输入为同次采集的 RGB、深度、实例 mask、标定和引用，输出为恢复深度/点云、支持区域与来源元数据。按现有 artifact/source_refs 传递，SDK 对象、权重路径和图像数组留在 Provider/Adapter 内。首个实现与 DFNet 对照共用此接口，不为模型增加公共 Tool 字段。

模型加载、释放和故障处理复用现有进程 worker 机制。部署配置描述所选模型、checkpoint、解释器、设备和输入变换。新机制保持无 USD/PhysX 依赖；Isaac 的 `perception_runtime.py` 注入它，`visual_perception.py` 组合它。推理不直接调用执行器。

新鲜度仍由 observation/revision/frame/calibration 确定；同一阶段不混用旧 mask、新深度或不同标定。模型估计和传感器值分开标记，未支持区域保持未确定。模型分数或有效深度比例不替代几何可信度。

## 分阶段实施

### P0：整理现有实现与失败路径

先保留 r2 输入作为错误深度、不可读标签、假瓶口和遮挡棒端的回归样本。将 `scene.understand` 中的感知实体与仿真物体身份解耦，允许离线输入得到独立实体和候选；已有实体刷新通过观测关联保持身份，关联不唯一时明确失败。

撤销/替换错误推断及依赖它们的测试：规则抓取、候选私自覆盖、标签边缘充当瓶口、可见棒端充当完整端点、从局部云声称完整物体尺寸。保留候选集合、坐标标定、新鲜度、碰撞、停止和单一结算机制。阶段失败分清“单个对象无几何”和“模型 worker 故障”，不吞掉底层错误。

交付：实际失败样本对应的无运动回归；一个没有仿真对象映射的 RGB-D 输入仍能完成理解与候选查询，运动准备则必须有明确执行对应。

### P1：完成模型输入适配与独立 worker

先接 ReMake 的几何输出，再以同一接口接 DFNet。分别验证官方样本，检查权重能否加载、输出是否有限且单位正确；之后才使用本项目输入。修复推理范围、尺寸和实际返回值适配，显式指定原始/输出像素关系。相对深度模型按 worker 生命周期加载，不逐帧重复加载。

当前瓶子种子原始深度约 1.799–2.425 m，而两个 builder 默认 inference 范围为 0.3–1.5 m；必须记录裁剪比例并按实际相机配置。扩大范围只避免清零，远距离泛化仍需测试。ReMake 内部示例为 640×480；原图为 1600×1200，输出不可误用 1280×720 默认值后直接配原内参。

交付：官方样本和 r2 的原始/过滤/ReMake/DFNet 结果，包含实际版本、权重来源、配置、时间及峰值显存。GPU/依赖不兼容属于部署失败，不得静默换成未训练权重或伪造输出。对照保持同一观测、mask、采样设置和后续 GraspNet。

### P2：取得任务所需观测

第三视角保留为全局布局和粗选依据。优先评估已配置的腕部相机是否能看清目标；需要改变视角时通过现有受控机械臂路径采集，或配置独立标定观察相机。相机位置是设备配置，目标位置和抓取点仍来自图像。观察运动不依赖待抓物体的规则抓取位姿，也不调用 benchmark 控制器。

每个实际目标至少取得：能读标签/判别类别的图像、能覆盖抓取接触区的图像，以及能识别过程功能点的图像。必要时为同一静止物体补充相邻视角，记录标定与场景状态。不会要求一次全局图把八个瓶子全识别成功；未看清的对象不影响已独立验证对象的查询，但不能被选作当前试剂。

**玻璃棒专门处理：** 先尝试从不同标定视角看清暴露棒段和工作端。若架子完全遮挡工作端，采用“完整相机观测登记＋当前可见棒段定位”的路径：同一根棒在可完整观察的安全状态下建立带来源的几何记录，之后用当前图像定位该物体并验证记录适用性。记录来自实际相机与恢复模型，不来自 USD 网格；它不提供固定抓取位姿，每次抓取仍由当前观测驱动 GraspNet。

已入架且没有完整观测记录时，如果安全取得完整观测的路径尚不成立，搅拌子任务保持未准备。不能为获取端点而先执行几何不足的抓取，也不能默认为已获得完整棒长。此时需先完成一次安全的完整观测采集；架子遮挡不是换一个模型就必然能解决的问题。

交付：目标标签可唯一关联到实例；瓶颈/瓶体接触区、杯口/瓶口及棒工作端的证据齐备。单视角恢复只证明受支持的表面，不自动证明整个封闭外形。

### P3：独立测量几何与功能点

在固定输入上分别比较四条处理结果。报告背景残留、几何覆盖、表面误差及误差分布，单列瓶颈接触区、瓶口/杯口中心和轴、棒径与端点。保持相同评估区域，避免只在模型自己声称有效的少量像素上计算低误差。

仿真 USD 由独立离线评估过程读取，只用于误差参考；推理 worker 不可访问它来补点、修正抓取或识别标签。图像像素变换、内参、深度单位先校验，不能靠拟合到 USD 的变换消除预测偏差。

从实际夹爪接触余量、过程净空和要求确定几何误差预算，并与已有运动误差共同评估；不通过放宽现有 3 mm 碰撞余量或 2 mm 跟踪容差掩盖感知误差。这些已有配置值不是模型精度证明。缺失表面和不稳定功能点明确保留失败。

交付：每个待执行对象的抓取几何和过程几何分别有通过/失败结论。只有完成这一阶段，才能把模型输出作为执行准备输入。

### P4：接入同一个 GraspNet 与准备链

将恢复点云沿既有 geometry_artifacts 传至 GraspNet，保存原始候选集、坐标约定、被选候选及准备结果。保持原候选顺序/筛选政策；准备逐候选检查时，只对候选本身不可行尝试下一项，基础设施失败或过期证据不能被掩盖。

明确 GraspNet 坐标到 TCP 的标定转换、接触参考点/深度、夹爪宽度与观测接触面是否一致。执行目标来自被选候选，仅作已说明的坐标变换；不读 USD 抓取点、不用私有缓存改写姿态。payload 碰撞几何必须覆盖有证据支持的物体范围，不能直接把露出棒段包围盒当作整根棒。

保留既有 `manipulation.prepare → object.acquire → manipulation.prepare_held → object.pour/tool.stir → manipulation.prepare_held → object.place` 顺序。第一版在 acquire 前具备该任务需要的功能点，避免额外引入“抓后补全”的新生命周期。持有后刷新源工具/容器观测时，沿用已选候选和持有收据，不因遮挡重新预测并选择一个抓取姿态。

原抓取候选作为 acquisition 历史证据保留；持有准备使用当前观测与持有收据，不能把旧候选改标为新观测，也不能将新物体姿态配上旧路线资格。

交付：模型候选未经覆盖、坐标/接触约定正确、执行身份对应明确，过期/缺点/缺功能点/取消均得到可定位结果；完整准备通过仍不算已执行成功。

### P5：原场景动作和 Agent 验收

按单对象抓取/归位、单次倾倒、单次搅拌、完整 Agent 任务依次测量。每项使用已准备路线，保留实际关节、夹持、物体运动、过程反馈和停止结果。倾倒角度/保持时间、搅拌半径/深度/圈数作为参数化过程规则；操作坐标来自已验证功能点。

最终示例指令：“选择可见标签 R01 和 R02 的试剂，按指定参数分别倒入目标烧杯，搅拌 2 圈后归位。”这是验收示例，实际标签必须现场读出并确认唯一，不按固定瓶位替代。更换两瓶位置再运行，验证选择跟随可见身份而非坐标；对不可读标签保留明确未确定。

验收记录区分契约测试、真实模型推理、无运动准备和仿真执行；整套任务只有在所请求动作与归位完成、持有状态正确、Runtime 结算一致时通过。模拟器的动作/过程反馈不自动证明真实传感器或真实液体实验效果。

## 失败分叉与本轮状态

- 官方样本加载失败：先修权重、依赖、设备或推理接口，不启动场景运动。
- 官方样本通过而原场景失败：优先检查裁剪/内参/尺度，再改善近景和视角；必要时采集有许可且留出测试场景的数据进行适配训练，另行记录实验。
- ReMake 和 DFNet 均不能恢复目标表面：有清晰边缘/法线证据时再引入 ClearGrasp；有真实标定 IR/RGB 时才比较 ASGrasp；有足够静态视角时再评估多视角重建。
- 几何通过但 GraspNet/准备失败：检查接触参考点、夹爪约束和路线；不产生规则抓取作为替代。
- 工作端完全遮挡且没有适用完整观测：先解决完整观测采集；不能宣称玻璃棒搅拌已经可执行。
