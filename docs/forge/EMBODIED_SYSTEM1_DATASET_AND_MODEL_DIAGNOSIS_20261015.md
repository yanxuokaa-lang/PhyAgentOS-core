# 面向模糊人类指令的具身 System 1：数据集与决策模型诊断

日期：2026-10-15。依据：用户本轮研究目标、当前仓库数据与实现，以及本轮核查的公开项目资料。

## 1. 研究目标与定位

研究包含两个相互支撑的目标：构建跨系统的具身决策数据集，训练一个低延迟的 System 1 决策模型。
核心问题是：结合对话、可见环境与执行状态，判断模糊指令如何理解，以及下一步应行动、观察、澄清、等待还是交给复杂推理。
PAOS 是验证环境之一；通用任务定义和标签应能映射到其他 Agent 框架、具身环境与执行策略。

用户所说的“训练 JEV”指训练 JEV 式结构化决策模型。现有 Laya 配置效果不佳是研究动机；其零样本表现不能直接代表领域微调后的性能。
数据集贡献应落实到任务覆盖、信息可见性、交互过程和跨系统测试；模型贡献应落实到正确性、校准、自主处理范围与完整系统成本。

Evaluation 路由分布：status_read 18、task_control 18、clarification_reply 6、system2 18；conversation 为 0。
Evaluation 状态分布：executing 27、terminal 6、none 12、paused 9、waiting_for_user 6。
每个评测家族的另外两条主要由句号、问号、语气词替换生成；60 次判断对应 20 个设计家族，其中存在重复输入。
两个 split 没有完全相同的 message，但 family_id 不重叠本身不能证明底层语义模板独立。

主要缺口：

- 场景集中于桌面整理；对象、目标、能力和执行过程变化不足。
- 多轮历史、指代修订、用户偏好、部分可观测环境、失败恢复和未知执行结果基本缺失。
- `mixed_or_unclear` 合并了多个明确意图、语义歧义和信息不足，应分开标注。
- 无当前任务时将状态查询送入 `system2` 属于特定系统处理策略，不是跨系统语义真值。
- 固定 task_ref 与固定状态模板可能形成记忆捷径；训练时应避免无关 ID 与标签绑定。
- 合成的 `paused` 是探针状态，不能直接视为当前 PAOS Task 枚举；真实实现还包含等待 Runtime、等待 Provider、取消中、等待重规划，并单独保存 pause_requested。

定位：保留这 60 条作入口回归测试，为新研究单独建立训练、校准和独立测试数据。
已有 Laya/Jev 结果见 [2026-10-09 实验报告](SYSTEM1_INTENT_ROUTING_COMPARATIVE_EXPERIMENT_REPORT_20261009.md)。

## 3. 数据单位：一个决策时刻

一条样本描述当前时刻可见的用户消息、对话、任务、环境、能力与执行事实，并标注下一步决策。
同一句“把那个杯子收起来”，在不同信息条件下应产生不同答案：

| 已知条件 | 信息缺口 | 下一步 |
|---|---|---|
| 历史已选红杯，目的地已约定 | 无关键语义缺口 | 选择相应操作能力 |
| 两个杯子，目的地明确，无选择线索 | 用户所指对象 | 询问对象 |
| 对象明确，但目的地被遮挡 | 环境可用性 | 获取观测 |
| 上一次抓取超时，物理结果未知 | 执行效果 | 核对结果和状态 |

区分三种不确定性：

1. 用户意图不确定：需要用户偏好、对象选择或目标说明。
2. 环境事实不确定：需要感知、状态查询或执行结果核对。
3. 模型能力不足：信息可能足够，但当前模型需要升级推理。

多个候选不一定构成必须澄清的歧义。“随便拿一个干净杯子”允许多个对象；应标注可接受答案集合。
对于确实无法从可见信息判断的用户偏好，正确标签可以是提问，而不是标注者私下知道的目标对象。

## 4. 任务集合

前六项是建议的首期核心任务，后四项用于扩展执行生命周期覆盖。

| 决策任务 | 示例 | 输出 |
|---|---|---|
| 交际意图与多意图 | “先停，再解释原因” | 意图集合、对象、先后关系 |
| 歧义与缺失信息识别 | “把它放回去” | 歧义类型、缺失槽位 |
| 指代与目标消解 | “刚才那个，换另一个” | 对象/地点/任务候选或未消解 |
| 信息充分性 | 当前信息能否支持下一步 | 足够/需用户/需环境/需复杂推理 |
| 信息获取与澄清选择 | 先问用户还是先看环境 | 信息源、查询目标、问题候选 |
| 下一步与能力选择 | 观察/等待/操作/回复/升级 | 通用决策类型和候选能力 |
| 指令修订与上下文更新 | “不是左边，是右边” | 替换对象、保留目标、更新约束 |
| 监控与恢复选择 | 超时、对象移动、抓取失败 | 核对、重观察、重规划、停止推进 |
| 完成与证据充分性 | 工具成功是否代表目标完成 | 满足/未满足/证据不足 |
| 子目标与候选计划选择 | 选哪个下一子目标 | 选择、排序、升级 |

System 1 可以选择“问哪个字段”或“问哪个候选问题”，由模板或其他模块生成自然语言话术。
工具在线状态、数值边界、权限和终结状态由原系统提供；决策模型消费事实，现有 Runtime 继续拥有执行检查。

## 5. 覆盖维度与家族定义

| 维度 | 覆盖内容 |
|---|---|
| 领域 | 桌面操作、厨房、整理、导航、配送、协作装配 |
| 指令形式 | 直接/间接请求、询问、纠正、否定、条件、复合、引用、假设 |
| 歧义来源 | 对象、空间参照、目标、数量程度、时间顺序、偏好、动作方式 |
| 对话 | 单轮、多轮、插话、撤销、跨轮指代、答非所问、旧回答失效 |
| 可观测性 | 充分、遮挡、缺失、过时、矛盾、对象移动或不存在 |
| 生命周期 | 未开始、执行、等待、暂停、取消中、完成、失败、效果未知 |
| 能力资源 | 可用、暂不可用、不支持、多候选、资源占用、不同本体 |
| 约束 | 禁止触碰、保持位置、顺序、轻拿轻放、偏好及约束冲突 |
| 复杂度 | 单对象、多对象、多条件、多意图、长历史、干扰信息 |
| 表达语言 | 中文、英文、自然口语、省略、错别字、ASR 噪声、中英混合 |
| 跨系统 | 工具名称、描述、返回格式、执行平台变化 |
| 答案形态 | 唯一、多种可接受、无可行候选、需信息、需升级 |

优先覆盖改变正确决策的组合：指代不明×多个同类对象、明确指令×过时观测、纠正×已执行、恢复×效果未知、多对象×允许任意选择。
新的语义家族应增加决策条件或推理结构；替换颜色、物品名和标点属于表达增强。
空间任务需区分用户视角、机器人视角和图像视角；程度词和历史动作引用也需独立覆盖。

## 6. 通用表示与标注

每条记录至少包括：

```text
用户消息与当前可见对话历史
任务目标、约束、当前子目标
可见环境与信息缺口
可用能力及执行状态
决策问题与候选解释/对象/问题/能力
可接受答案、所需补充信息、标注依据
来源、原始 episode、派生关系与 split
```

模型输入与评测真值分离：模拟器隐藏状态、未来用户回答、事后成功结果只能进入相应标签或评测器。
通用标签使用 ask_user、request_observation、select_capability、wait、replan 等语义；具体 handler 和工具名称由各系统适配。
分别评测工具命名变化、环境变化、Agent 框架变化，避免把一种泛化等同于另一种。

按组构造反事实：保持指令不变，只改变关键状态；保持状态不变，只改变约束；增加无关信息检查稳定性。
保持原始场景、改写、翻译、反事实和同 episode 前缀在同一 split，防止派生数据泄漏。
双人独立标注并裁决争议；多种可接受行为保留集合，对缺失信息和标注依据作简明记录。

[KnowNo](https://github.com/google-research/google-research/tree/master/language_model_uncertainty) 是重要方法对照：研究机器人何时求助，并使用 conformal prediction。

AmbiK、REI-Bench、DialFRED 已覆盖歧义和求助的多个部分，因此新贡献需明确新增的领域、状态、决策类型及泛化能力。

## 8. 模型与训练路线

建议共享编码器，结合三类输出：

1. 诊断：意图集合、歧义类型、缺失信息。
2. 候选评分：对象、目标解释、澄清问题、能力。
3. 下一步决策：处理、获取信息、等待、执行候选、升级，并输出可校准概率。

候选采用描述与动态 ID；提供无合适候选/信息不足选项。单独测候选召回率和候选内判断质量。
候选优先来自对象列表、能力注册表或轻量检索；如依赖大模型生成，计入整条链路时延与费用。
文本化环境作为首期输入时，感知位于模型之前；完整模拟器状态实验与实际感知输出实验分别报告。

训练顺序：监督分类/排序和多任务基线 → 状态反事实及困难负例 → 独立校准 → 有可靠交互环境后研究任务收益驱动的优化。
复杂 RL 或官方 Jev 内部训练方式复现不是前置条件；先验证数据和决策任务能否带来跨域收益。

## 9. 评测与对照

| 层面 | 指标 |
|---|---|
| 意图/歧义 | Macro-F1、多标签 F1、逐类召回 |
| 指代/目标 | 候选召回、候选内准确率、可接受集合命中率 |
| 获取信息 | 必要澄清召回、不必要提问率、信息源选择准确率 |
| 澄清收益 | 回答后消歧率、问答轮数、完成率提升 |
| 决策 | 正确率、错误直接行动率、漏升级率 |
| 概率 | NLL、Brier、校准误差、风险—覆盖率曲线 |
| 状态敏感性 | 关键变化响应、无关变化稳定性 |
| 完整任务 | 成功率、约束违反率、恢复率、System 2 调用次数 |
| 效率 | 决策/完整请求 p50/p95、成本、内存、超时和失败 |

主要比较：相同错误水平下自主处理更多请求；相近任务成功率下减少大模型调用、用户提问与总等待时间。
始终升级和始终提问均应纳入简单对照，展示质量与自主性/交互成本的取舍。
置信区间按 episode 或家族聚合；完整失败分母与仅有效响应指标分别报告。

测试集合：分组 IID、未见领域、未见歧义组合、未见工具/描述、独立自然用户表达。
公开基准保留原协议时可比较原指标；转换成候选分类后报告派生评测，不能沿用原排行榜结论。

对照组：规则+状态规则、多语言编码器分类、候选联合编码排序、Laya 原始与领域微调、小型生成式结构化模型、强 LLM 完整处理、KnowNo 类求助策略。
消融：去环境、去历史、去歧义辅助任务、去反事实训练、去校准，以及真实候选与理想候选。
各组共享候选生成、感知和执行器；版本、数据量、计算预算与延迟口径明确记录。

## 10. 分阶段实施建议

1. 标注试点：约 300–500 个独立情境，覆盖四类场景和前六类任务；先检验标签与争议裁决。这是预算建议，不是泛化充分性结论。
2. 跨来源数据：从允许使用的公开训练集抽取决策时刻，补自然表达、反事实和执行异常；先划分原始场景再增强。
3. 首轮模型：同数据比较上述基线；记录数据/模型版本、配置、种子和逐样本输出，保留独立校准集。
4. 多环境验证：文本/家庭交互环境与 PAOS+RoboTwin 操作环境各选一个，再评测第二种 Agent 接口或框架。

按独立情境数、决策时刻数和表达变体数分别报告规模；依据学习曲线和类别误差决定扩充方向。
每次训练评测使用独立输出目录，保留配置与指标；不要覆盖旧实验。

## 11. 可验证的研究主张

数据集：跨场景、跨任务阶段，显式区分用户意图不确定、环境信息不足和模型能力不足，包含状态反事实、有效澄清和跨系统测试。
模型：联合诊断、信息获取选择和下一步决策，在未见场景中以可测量的错误水平减少复杂模型调用和交互成本。
