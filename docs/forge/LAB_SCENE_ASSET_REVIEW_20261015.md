# 实验室场景构建与真实资产来源复审

日期：2026-10-15。范围：审核并修订场景与资产方案；本条不交付真实资产转换后的场景或机器人动作验收。
用户要求：RoboTwin/Franka、无液体、开口试剂瓶、稳定杯座、带可抓握柄的手持搅拌棒、更多桌面物品、瓶身可见标签、目标受阻时先清障。

## 1. 审核结论

推荐保留 RoboTwin/SAPIEN 与当前 Franka 执行栈，优先从 LabUtopia 提取真实实验室网格和贴图，
转换成逐物体资产后重新装配实验台。RoboTwin 本地物体库补充合适的干扰物。
原先圆筒/方块拼装图已被用户否定，不作为最终场景继续扩展；它仅证明程序化资产装载曾经运行。

目前确认的是资产来源、文件可下载和部分真实网格存在。尚未确认转换后的外观、开口几何、
标签可读性、Franka 可抓性及整段路线。因此“方案可继续推进”不等于“场景已经可执行”。

| Major | 18 个 actor 的程序化预览没有机器人，不能确认工作空间 | 沿用真实 Franka 安装位姿、桌面、head/wrist 相机与标定装配，随后做带持物几何的路线检查 |

| Major | 新端点离线测试可能被误报为场景闭环 | P1 状态接续与 P2-P6 真实任务适配、运动、识别及清障分别记录完成状态 |

## 4. 放置环境怎样构建

### 4.1 两层装配：实验室外观与机器人工作台

保留当前 RoboTwin 的 Franka 配置、控制时步、关节与夹爪参数、相机和标定链。
在 `Base_Task` 对应接缝增加实验室 task/profile 与薄 Adapter，不能只改 RGB 方块任务的名字。
当前 `robotwin_persistent_engine.py` 仍选择 RGB task adapter，并包含 RGB 预留实体映射，需要显式接通新任务。

现有 Base_Task 桌面名义尺寸是 1.2 m × 0.7 m、名义高度 0.74 m，另有 table bias；这些值来自源码，
最终使用当前 profile 的实际桌面变换。导入实验台模型时，对齐操作台面、去除重复碰撞面，
不直接采用来源场景中的桌高、Franka 底座或相机位姿。

背景的柜体、仪器与墙面采用真实静态模型；机械臂可能接触或遮挡视线的部分纳入碰撞/观测。
操作区保留独立的动态瓶子、工具和挡物；不可把整张实验台合并后只做一张视觉背景。

### 4.2 桌面布局

建议目标规模约 18–24 个桌面对象，数量随可达性和实际器材尺寸调整：
8 个带标签试剂瓶、1 个接收烧杯、1 根带柄棒、杯座/棒架 2 件、5–10 件实验用品、1–2 件可移动挡物。
这是一项目标规格，未宣称全部资产已经取得。实验用品优先选择量筒、锥形瓶、试管架、托盘等实际模型。

以机器人操作侧看，中央保留倒液/搅拌操作区，右或左近侧设棒架，瓶子在两侧或后部错列，
一侧留独立的清障暂存区。大仪器放远侧背景，不占夹爪通道。
对象间距按夹爪包络、持瓶扫掠空间、进出杯口路线与观测视线确定，不能平均撒满桌面。
先验证 2 瓶动作骨架，再填充同一场景到目标数量；最终交付仍须达到丰富桌面的要求。

### 4.3 真实资产的视觉与碰撞分别准备

1. 取得选定 USD 及相对引用的子 USD、纹理、材质，记录来源/许可/改动。
2. 按物体拆分、保留局部坐标与 UV，确认米制、轴向、法线和实际尺寸；导出 GLB 或 OBJ+MTL+纹理。
3. SAPIEN 3 的 USD 导入内部调用 Blender 转换。当前 PATH 未找到 Blender，检查的两个 Python 环境也没有 bpy；不能假设直接 `add_visual_from_file(usd)` 就成功。
4. OmniGlass、OmniSurface、MDL 不保证自动映射；用原贴图重建相容材质，玻璃的折射/透明效果需实际渲染比较。玻璃深度质量也要在相机输出中测量。
5. 动态瓶/杯采用分部凸碰撞或经过验证的凸分解，杯口与内腔保持可进入。静态背景可用合理简化碰撞；不通过把整个杯子做单凸包来省事。
6. 标注瓶口/杯口/杯内可用区域/棒尖/握柄。模型尺度或握柄改动后重做质量、惯量、抓握和碰撞检查。

稳定杯座和棒握柄可以按尺寸专门设计为 CAD 夹具；应标为自制功能件。
其简化碰撞体可以是基本几何，最终可见实验器材仍使用来源网格。固定杯座不自动意味着固定杯体。

### 4.4 瓶身标签与后续识别

保留来源瓶体材质，在真实 UV 区域或贴合表面的贴片上增加实体标签，不能只把名字写进 JSON。
标签含试剂身份；A–H 是当前占位命名，不是用户已经指定的真实试剂列表。
同一瓶型可生成不同标签，位置/标签独立变化；瓶型选择完成后才确定标签曲面与尺寸。

用实际 head/wrist 相机输出验证读字，不能依赖 1600×1200 的独立 inspection 相机截图。
后排遮挡先通过错列、较大标签、多面标签和现有多视角缓解；仍看不清时，需要受支持的补充观测步骤，不能读环境 actor_id 当答案。
透明物体的观测几何如果缺失，要补有观测证据的已知模型位姿拟合等能力；该能力当前不能假定已有。
原始仿真位姿可以供开发专家与评分使用，不能冒充标签识别结果。

### 4.5 “受阻先清障”必须形成真实前置条件

用可抓取的试管架/托盘等对象作为挡物候选，保留其暂存位置与搬运路线。
比较相同目标和相同候选抓取集合：无遮挡可行，受阻不可行，移开挡物后恢复可行；同时确认
挡物本身可达、能暂存、没有与目标瓶初始穿模。这里验证的是当前控制/抓取配置下的阻挡，
不是证明所有可能机械臂轨迹都无解。单次规划器返回失败也不足以证明真正受阻。

清障分支由图像/几何及准备结果触发，不能把 `blocked_label` 或 seed 直接交给 Agent 选择脚本。
标签遮挡与机械抓取受阻分开测试；否则成功可能只是预先给出隐藏目标答案。

## 5. 调整后的实施顺序及产物

| 阶段 | 操作与依赖 | 可审阅产物/完成标准 | 失败时的处理 |
| --- | --- | --- | --- |
| A 资产取得 | 优先取得 LabUtopia lab_003 及依赖，选择瓶/杯/棒/架/实验台 | 逐物体来源、许可、原始预览与几何清单；广口试剂瓶仍须筛选 | 缺开口或瓶型不合适时换模型或明确修网格，不能用封口瓶继续 |
| B 转换验证 | 单独转换一个瓶、一个杯和一件架；装入 SAPIEN | 真实材质近照、开口剖面、碰撞体检查、尺度测量 | 修材质、重建分部碰撞；尚不可用就不批量复制 |
| C 环境装配 | 原 Franka+相机+实验台；2 瓶、杯座、棒架起步 | 实际机器人相机的 RGB/depth，稳定性与单次路线结果 | 先调整支撑/尺寸/机器人可达布局，再加杂物 |
| D 标签与动作 | 图像选瓶、抓持、倾倒、持物归位，棒尖变换与搅拌 | 分段真实执行、过程测量、失败与停止证据 | 区分感知、抓取、路线及终态失败，不能重放 unknown 倾倒 |
| E 丰富与受阻 | 扩充到目标数量，加入可移挡物和合法暂存区 | 同提示无遮挡/受阻对比、实际清障计划及完整任务视频 | 无可行暂存位置则改布局或明确报告；保持用户试剂顺序 |
| F 集成验收 | 接上现有 Coordinator/Runtime/Skill 方法与打包链 | 原抓放兼容；两瓶顺序+搅拌+归位；识别与执行证据分开 | 不以端点 Fake 测试、静态图或漂亮渲染替代闭环 |

下一项具体工作是 A/B：选定真实瓶、杯、棒/架并完成一组材质与碰撞转换。
先交付这组真实资产在 SAPIEN 中的检查结果，再按 C-F 推进；不再沿用被否定的圆筒外观。
