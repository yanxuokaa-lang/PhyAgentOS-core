# 独立创新方向：VLM 与 VPP2 之间的 System 1 桥接决策模型

日期：2026-10-15。
研究主题：面向具身任务的目标忠实性与状态感知执行决策。
状态：研究方向提案；文中的机制收益是待实验检验的假设。

## 1. 一句话定义

在高层 VLM 规划器与底层 VPP2 动作策略之间，引入轻量 System 1 决策模型，结合原始用户意图、已确认信息、当前观测和执行反馈，判断下一步应继续、切换子任务、补充观察、向用户澄清还是请求重规划。

核心研究问题是：**怎样让上层“说得详细”的指令，在当前场景中仍然忠实于用户目标，并在执行变化时及时调整？**

暂定英文方向名：Intent-Preserving, State-Aware Bridging for Hierarchical Embodied Agents。
VPP2 是首个验证后端；方法接口按语言条件策略设计，后续可接其他动作策略或技能执行器。

## 2. 为什么这个位置值得研究

高层 VLM 生成了详细子任务，只说明语言已经具体化；能否直接执行还取决于目标依据、当前对象、策略能力和任务进度。

| 失配类型 | 典型场景 | 中间层要解决的问题 |
|---|---|---|
| 详细描述加入了无依据的选择 | “拿我的杯子”被扩写成“拿红杯” | 判断颜色选择是否有用户确认或其他可靠依据 |
| 指令与当前场景不一致 | 指令指向左侧杯子，但杯子已经移动 | 更新对象绑定，必要时重新观察 |
| 语义成立但策略能力不匹配 | 提议完成当前夹爪或策略不支持的操作 | 选择已支持的方法，或交回高层重新规划 |
| 执行进度与计划不同步 | 动作块结束，但物体仍未放进容器 | 依据观测判断继续、核对或恢复 |
| 任务中途变化 | 用户补充“不要拿蓝杯”或取消任务 | 将新约束传给任务管理器并处理在途执行 |

这些问题需要同时比较“用户想要什么”“高层建议什么”和“现场实际发生了什么”。只检查指令格式、关键词或文本相似度无法覆盖这种关系。

## 3. 与已有 VLM＋VPP2 的区别

VPP2 官方论文第 3.3 节已经采用高层 VLM 进行子任务规划、语义理解和记忆。因此，增加高层规划器本身属于已有方案。
本方向拟研究的增量是一个**保留原始意图、读取执行状态、按需升级的可学习桥接策略**。

| 已有或直接可做的方案 | 本方向需要证明的增量 |
|---|---|
| VLM 拆解任务，再交给 VPP2 | 发现详细子任务中未经确认的选择及执行失配 |
| 提示词增强，将描述写得更具体 | 根据证据决定是否应执行，而不只是扩写文本 |
| 固定规则决定何时调用大模型 | 在变化的状态中学会信息获取与复杂推理升级 |
| 固定动作或工具名称分类 | 判断目标、对象、能力和进度之间的关系 |

方向是否形成独立方法贡献，取决于上述机制相对已有方案的实测增益，以及进一步相关工作检索后的差异定位。

## 4. 架构与职责

```text
原始用户请求、已确认偏好 ──────────────┐
              │                    │
              ▼                    ▼
高层 VLM：提出子任务与候选 ──→ System 1：桥接决策
                                     ▲       │
                 当前观测、执行反馈 ────┘       ├─ 缺用户信息 → 澄清
                                     │       ├─ 缺环境事实 → 观察
                                     │       ├─ 复杂失配 → VLM 重规划
                                     │       ▼
                                     │   任务管理器＋策略 Adapter
                                     │       ▼
                                     │   VPP2：生成连续动作块
                                     │       ▼
                                     └── Runtime / 环境执行
```

- 高层 VLM 负责开放式目标理解、候选子任务与复杂重规划。
- System 1 负责当前决策点的判断和选择；“快”体现为较低的决策成本，而非预先承诺固定毫秒数。
- 任务管理器保存任务、约束、进度与取消状态，并应用决策；System 1 不另建一套执行状态真值。
- Adapter 将选择结果转为 VPP2 的文本、图像和本体状态输入，处理动作表示与归一化。
- VPP2 产生连续动作块；Runtime / 环境执行并返回实际结果。

## 5. 候选核心机制

### 5.1 原始意图保留：检查具体化是否有依据

System 1 同时读取原始请求与 VLM 提议。它检查新增的对象、目的地、顺序和限制是否由用户确认、上下文或当前证据支持。
同一句“拿红杯”，在用户已确认红杯属于自己时可以执行；在所有权未知时应澄清。决定行动的是证据，而不是句子是否详细。

若环境描述全部来自同一 VLM 的同一次错误判断，纯文本桥接模型也难以独立纠错。需要视觉核对的情况应取得额外观测或升级给具备相应能力的模块。

### 5.2 状态感知选择：判断此刻该做什么

建议以原始请求、已确认约束、候选子任务、当前观测、执行历史和策略能力作为输入。
首期采用轻量候选评分与决策类别预测：选择已提出的子任务或处理方式，同时识别缺失信息；开放式方案生成交由高层 VLM。

| 决策 | 触发依据 | 下游行为 |
|---|---|---|
| 继续 | 当前子任务仍适用且尚未完成 | 保持子任务，生成下一动作块 |
| 切换 | 当前后置条件已满足，下一子任务适用 | 由任务管理器更新子任务 |
| 观察 | 缺少对象位置、执行结果等环境事实 | 获取相关观测后重新判断 |
| 澄清 | 缺少用户偏好、所有权或目标选择 | 提出具体问题，等待回答 |
| 重规划 | 当前候选均不适用，或问题需要复杂推理 | 将失配原因及证据交给高层 VLM |
| 等待／结束 | 在途动作尚待确认，或整体目标已达成 | 由任务管理器维持等待或结束任务 |

如果要输出“执行成功概率”，需要用相应执行结果训练和校准；普通分类置信度不能直接解释为物理成功率。

### 5.3 事件触发升级：减少重复推理

在任务开始、子任务边界、明显场景变化、用户插话或执行异常时触发桥接决策。
常规动作生成继续由 VPP2 处理；只有缺少关键信息或超出轻量模型处理范围时才调用高层 VLM。
应将候选生成、感知、文本编码和回退成本一并计入，验证节省是否真实发生。

### 5.4 依据执行结果续接：区分预测、完成与未知

预测视频表达模型预期；动作块结束表达一段控制已执行；子任务成功则需要实际后置条件证据。
对于“结果未知”，先核对是否已产生物理效果，再决定下一步，避免把未知一律当作失败重试。

## 6. 一个完整例子

用户说：“把我的杯子放进托盘。”桌上有红杯、蓝杯，所有权未知。

1. VLM 提议“抓起红杯并放入托盘”。System 1 对照原始请求，发现红杯选择缺少依据，询问“红杯还是蓝杯是你的？”
2. 用户回答“蓝杯”。任务管理器保存已确认信息，VLM 或已有候选提供蓝杯子任务。
3. System 1 核对当前对象与策略能力，选择执行；Adapter 将子任务转成可区分蓝杯的描述，交给 VPP2。
4. 一段动作结束后，最新画面中夹爪遮住杯子。System 1 选择补充观察，不据动作块结束直接判定成功。
5. 观测确认蓝杯已在托盘中，任务管理器据完成条件结束任务；若观测显示未抓起，则根据当前状态选择恢复或重规划。

若对话早已确认蓝杯属于用户，第 1 步应直接使用确认信息，避免不必要提问。

## 7. 落到 VPP2 接口上的接入方案

已有源码诊断确认：VPP2 的策略路径接收自然语言、图像、本体状态及相应版本支持的历史，返回连续动作块。
例如 RoboDojo Adapter 的 `_infer_action_chunk(observation, instruction)` 将子任务文本传入策略推理，再截取动作执行前缀。
因此首期接入点放在**任务管理器与 VPP2 策略 Adapter 之间**，保留内部 Video DiT—Action DiT 路径。

接入需要处理四个具体边界：

1. 新子任务影响后续推理；已排队的旧动作由执行所有者取消或完成，修改指令字符串不会自动停止它们。
2. 子任务切换与 episode reset 分开；后者可能清除历史条件。
3. 动作块完成与子任务完成分开；后者使用实际观测和完成条件。
4. 对象 ID 是上层引用；若下层仅接受文本，Adapter 仍需生成当前场景中可区分对象的描述。

System 1 输出的是语义决策，不直接生成关节命令，也不取代现有运动约束和停止机制。
具体接口可追溯到文末官方源码；其他 VPP2 配方的输入、动作空间与历史处理需分别适配。

## 8. 怎样检验这一创新方向

### 8.1 主要假设

- 目标忠实性：保留原始请求，能降低未经确认的对象、目的地或顺序选择造成的错误。
- 状态感知：加入观测与执行反馈，能减少过早切换、无效继续和结果未知时的错误重试。
- 成本收益：在可比的任务正确性下，事件触发的小模型决策能减少高层调用或总耗时。
- 可迁移性：替换高层 VLM 或下层策略后，核心决策机制仍有收益。

### 8.2 对照与消融

主要对照为 VLM＋VPP2、VLM＋规则桥接＋VPP2、VLM＋通用小模型＋VPP2，以及拟训练的桥接模型。
对照中的 VLM 同样采用合理的事件触发方式，避免以不必要的高频调用夸大成本优势。
使用理想桥接决策配合同一 VPP2，估计错误中有多少来自下层执行能力。

分别移除原始用户请求、已确认信息、当前观测、执行历史和按需升级机制，观察各机制的独立作用。
比较时保持任务、初始场景、候选生成器、感知来源和动作策略配置一致；调度变化单独记录。

### 8.3 重点指标与判断依据

| 指标 | 回答的问题 |
|---|---|
| 原始用户目标完成率 | 是否真正完成用户想要的任务，而非仅完成 VLM 改写后的任务 |
| 错对象／目的地／顺序率 | 目标忠实性机制是否有效 |
| 不必要澄清、漏澄清与漏升级 | 是否兼顾自主执行与必要的信息获取 |
| 过早切换、无效继续与恢复成功率 | 是否改善执行过程决策 |
| VLM 调用数、总耗时及 p95 决策延迟 | 新层的收益是否覆盖自身和回退开销 |

报告逐任务结果、配对差异与不确定性，避免只用平均成功率解释所有收益。
增加规划或额外感知后的 agent 评测，应与官方 direct-policy 协议分开报告。

## 9. 分阶段推进路线

1. **确定真实问题。** 在一个可运行的 VLM＋VPP2 环境中记录目标、子任务、观测与执行结果，确认错误是否发生在桥接位置。
2. **验证决策机制。** 离线比较规则、通用小模型与拟训练模型；以只记录建议的方式检查目标失配和切换判断。
3. **验证闭环收益。** 在仿真中接入决策，分别测目标完成、错误行动、恢复与完整系统成本。
4. **验证迁移范围。** 更换高层 VLM 或增加第二种执行后端，区分通用机制收益与 VPP2 专属适配收益。

若错误主要来自底层动作能力，优先调整实验任务和问题定位；若小模型没有成本或正确性优势，重新检查输入信息、候选质量与升级策略。
首期采用外置语义与状态输入。读取 VPP2 视频潜变量属于后续分支，适用于确有视觉预测证据需求且可承担后端耦合的研究。

## 10. 方向表述与资料依据

可用于后续讨论的贡献表述：

> 研究一种面向分层具身智能系统的轻量桥接决策模型，在保留原始用户意图的条件下，联合当前观测与执行反馈选择子任务续接、信息获取和高层重规划，实现从语言计划到动作执行的状态感知协调。
