# v12.4.7 Seven-Dimension Review

## Findings

No Blocker or Major findings remain.

Minor residual risk: `ProcessWorkerResourceError` treats SIGKILL/137 as a
resource-exhaustion signature. That matches the recorded Runtime cgroup OOM
incident, but a human-issued SIGKILL has the same process-level signal. The
original return code and stderr tail remain available for operator diagnosis,
and the result is fail-closed in either case.

## Review dimensions

1. **Architecture**: resource classification stays in the existing
   `JsonlProcessWorkerClient` seam; provider-specific mapping stays in the
   RobotWin Grasp adapter; synchronized-view enforcement is an opt-in
   Runtime/Skill composition policy. No parallel executor, provider fallback,
   or simulator-truth path was introduced.
2. **Functionality**: the GraspNet profile forwards a bounded point budget,
   caps worker sampling, and reports resource/termination-specific unavailable
   codes. A RobotWin profile with `sensor_refs` produces a live ToolSpec that
   rejects `sensor_ref` and requires two unique views. Core single-view
   observations remain valid when the policy is disabled.
3. **Compatibility**: legacy `sensor_ref` runtime profiles and the generic
   provider-neutral observation endpoint remain supported. The fake Gateway
   remains single-view because it is a compatibility fixture; the production
   RobotWin profile opts into the stricter policy explicitly.
4. **Safety**: all worker failures remain Query `unavailable`; no candidate,
   readiness, Action, or motion authorization is fabricated. The dual-view
   rule blocks incomplete identity/geometry evidence before planning. Existing
   terminal-result, fresh-revision, binding, collision, IK, and authorization
   gates are unchanged.
5. **Recovery and AgentLoop**: the typed provider error gives the existing
   fail-closed recovery path a stable reason and does not create a retry or
   replacement invocation. The observation ToolSpec rejects invalid
   single-view arguments before Gateway/provider execution, so no stale record
   is created or reused.
6. **Provenance and observability**: worker return code and bounded stderr tail
   are retained on the process exception and logged by the adapter; public
   responses preserve scene/request identity and expose the bounded error code.
   Multi-view records continue to carry per-view provenance, common revision,
   calibration, and measured skew.
7. **Tests and release**: focused adapter, Runtime, contract, observation,
   host, deployment, and AgentLoop tests pass (106 tests). Ruff,
   `compileall`, and `git diff --check` pass. One pre-existing
   `test_binding_freeze` assertion is stale against the already-published
   manifest's extra `task.goal`/`manipulation.staging` tools and is unrelated
   to this change. The rebuilt Node archive SHA is
   `c83d8a8ccb86d2fd10373aecdee738c76f80130cb48afc506efbd8954443ca08`, the
   Skill lock was updated to that exact value, and the formal Skill bundle
   build passed.

updated Node/Skill bundle is installed and the old Runtime is stopped. Physical
