# re:へいたん

X（旧 Twitter）のタイムラインから誹謗中傷を取り除く Chrome 拡張。
[へいたん](https://github.com/kamesan1577/jisshu4-g11-t4-frontend) のタイムライン検閲を、
TypeSafe の System One モデル **jev** に載せ替えたものです。

対象はタイムラインに流れてくる投稿の検閲です。jev は文字列を生成しないため、
攻撃的な文を書き換えて提案する機能は含みません。

## なにが変わったか

旧実装は、拡張 → AWS Lambda（FastAPI）→ OpenAI → Redis という経路で
GPT-3.5 に「この投稿の安全性レベルを JSON で返せ」と頼んでいました。
jev は文章を作らず、型の付いた判断だけを 70〜500ms で返します。
生成を捨てるかわりに速いので、経路そのものが要らなくなります。

|              | へいたん                                   | re:へいたん                        |
| ------------ | ------------------------------------------ | ---------------------------------- |
| 判定         | GPT-3.5 に JSON を書かせる                 | jev の score / noul                |
| 経路         | 拡張 → Lambda → OpenAI                     | 拡張 → jev                         |
| キャッシュ   | Redis（upstash）                           | 拡張内（メモリ + storage、7 日）   |
| バックエンド | FastAPI + Lambda + Redis                   | なし                               |
| 投稿数の増え方 | 1 投稿 1 リクエスト                      | 8 投稿 1 リクエスト                |

判定のパースエラーも消えました。jev の答えはスキーマに従うので、
`json.loads(...)["level"]` が落ちる経路が存在しません。

## 判定のしかた

旧実装は 1 本の長いシステムプロンプトに判断基準を詰め込んでいました。
jev には文章を渡せないので、同じ基準を独立した質問に割り、合成はコード側で行います。

```
sev     score  読み手を傷つける度合い（3 段階）
attack  noul   特定の個人・集団を貶める意図があるか
slur    noul   侮蔑語・差別語・人格否定を含むか
threat  noul   暴力や危害をほのめかしているか
sexual  noul   相手を辱める性的表現を含むか
banter  noul   内輪のノリ・自虐・愛のある誇張か
```

`banter` は減点側の証拠です。「マジ尊い…死ぬ…」を脅迫と取り違えないために、
強い語そのものではなく敵意の有無を別の軸で測っています。ただし `attack` や
`threat` が強いときは減点を効かせません（`src/core/verdict.ts`）。

閾値を超えたら隠す／ぼかすですが、jev の confidence が低い判定では
Blocked まで踏み込まず Veiled で止めます。自信のない判定でタイムラインが
静かに欠けるのを防ぐためです。

## 速くするためにやっていること

- **質問のまとめ送り** — `state` は 1 度しか読まれないので、8 投稿を 1 リクエストに
  詰めると往復が 8 分の 1 になります（設定で 1 投稿ごとの精度寄りモードに切替可）。
- **拡張内キャッシュ** — 保存しているのは表示レベルではなく jev の確率そのもの。
  感度を動かしても問い合わせ直しが起きません。TTL は旧実装と同じ 7 日。
- **見えるものだけ判定** — `IntersectionObserver` で画面から 600px 以内に
  入った投稿だけをキューに入れます。旧実装は DOM が動くたびにタイムライン全体を
  送り直していました。
- **送るまでもない投稿を弾く** — URL だけ、絵文字だけ、メンションだけの投稿は
  API に出しません。
- **同文の重複排除** — 同じ本文は、同時に来ても 1 回しか問い合わせません。

判定が返るまで投稿をぼかしておく設定が既定で有効です。旧実装の数秒では
実用になりませんでしたが、1 往復なら間に合います。

## デモ・画面共有のための目隠し

実際のタイムラインを録画したり画面共有したりするとき、投稿者を伏せられます。
ポップアップの「投稿者を伏せる」で ぼかす / モザイク / 塗りつぶす を選びます。

隠れるのは、アイコン、表示名、@ID、「◯◯さんがリポストしました」、
本文や「返信先:」に出てくる @ メンション、おすすめユーザー、ホバーカード、
左下のアカウントボタン。投稿の本文は隠れません。

検閲の ON/OFF とは独立しているので、「検閲を切った素のタイムライン」と
「検閲を入れたタイムライン」を同じ条件で撮り比べられます。

ぼかしとモザイクは、解像度と元画像によっては推測されうる処理です。
公開する動画なら塗りつぶしを選んでください。

## 動かす

```sh
npm install
npm run dev      # 開発用ビルド + 自動リロード
npm run build    # .output/chrome-mv3 に本番ビルド
npm test         # 判定ロジックとリクエスト組み立てのテスト
```

`chrome://extensions` で「パッケージ化されていない拡張機能を読み込む」から
`.output/chrome-mv3` を指定してください。

API キーは拡張の設定画面から登録します（[console.typesafe.ai](https://console.typesafe.ai) で発行）。
キーは background service worker だけが読み、X のページ側には渡りません。

### 素振り

拡張を読み込まずに、判定とレイテンシだけ確かめられます。

```sh
TYPESAFE_API_KEY=... npm run probe
```

旧実装のプロンプトが「変換する／しない」として挙げていた文をそのまま流し、
solo モードと pack モードの所要時間と入力トークン数を並べて出します。
閾値を詰めるときの出発点に使ってください。

## 構成

```
src/core/       判定の中身。DOM も chrome API も知らない部分
  jev.ts          System One の HTTP クライアント（再試行つき）
  questions.ts    質問セット。solo と pack の 2 通り
  verdict.ts      確率を 1 本のスコアに畳み、表示レベルに落とす
  cache.ts        メモリ + storage の 2 段キャッシュ
  moderator.ts    重複排除・まとめ送り・同時実行数
src/content/    X の DOM を読む部分と、判定を見た目に反映する部分
src/entrypoints/ background / content script / popup / options
```

判定ロジック（`core`）は Chrome API に触れないので、Node からそのまま呼べます。
`scripts/probe.ts` と `test/` が同じコードを走らせているのはそのためです。

## 既知の弱点

- jev は英語がいちばん得意で、日本語を含む CJK は「扱えるが同等ではない」と
  [ドキュメント](https://docs.typesafe.ai/models)に明記されています。
  日本語のタイムラインで使う以上、閾値と confidence の下限は実際の
  タイムラインで詰める前提で考えてください。`npm run probe` はそのためにあります。
- 投稿の取得は X の `data-testid` に依存しています。壊れた場合は判定が
  行われなくなるだけで、タイムラインは素通しになります。
