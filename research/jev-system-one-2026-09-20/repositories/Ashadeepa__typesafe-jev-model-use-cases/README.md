# typesafe-jev-model-use-cases

Small, runnable demos of [TypeSafe](https://docs.typesafe.ai)'s System One model (Jev) —
each one shows a different primitive solving a task that would otherwise mean
hand-rolled parsing, keyword matching, or scraping an answer out of LLM-generated prose.

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # fill in TYPESAFE_API_KEY
export $(cat .env | xargs)
```

## Use cases

### 1. Parallel processing check — `run.py` (Noul)

Judges the same batch of 16 sample support tickets ("is this about billing?")
sequentially, then again concurrently via `ThreadPoolExecutor` (the pattern from the
[rerank cookbook](https://docs.typesafe.ai/cookbooks/rerank_typesafe.md)), and prints
wall-clock time for both plus token usage, so you can see the actual speedup.

```bash
python run.py                  # default: 8 workers, all 16 tickets
python run.py --workers 16     # one worker per ticket
python run.py --limit 4        # smaller batch
```

Output shows sequential vs. parallel wall-clock time, the resulting speedup, and
whether both runs agreed on every ticket (the model isn't deterministic, so a
mismatch here and there is expected, not a bug).

**What we found:** independent TypeSafe calls are small and fast enough that fanning
them out gives a consistent ~4.5–5x speedup at no extra token cost, with identical
results either way. Don't loop over a batch of judgments — parallelize it.

### 2. Citation / claim check — `citation_check.py` (Choice)

A hallucination detector: 3 short policy documents and 8 claims that "cite" them (as
if generated by a support chatbot). Each claim is checked against its source with a
3-way `Choice` — `supports` / `contradicts` / `says_nothing` — instead of a plain
yes/no, because "does this claim match the source" genuinely has three outcomes, and
collapsing "contradicts" and "made up" into one "no" would hide the difference between
*wrong* and *unsupported*. Pattern from the
[citation check cookbook](https://docs.typesafe.ai/cookbooks/citation_check.md).

```bash
python citation_check.py
```

Prints a verdict + confidence per claim, flags anything below a confidence threshold
for human review, and lists every claim that needs a second look (contradicted,
unsupported, or low-confidence).

**What we found:** correctly separated 2 true statements, 4 subtly-wrong statements
(wrong number, wrong condition, or the flat opposite), and 1 fabricated detail with no
basis in the source at all — with no string parsing involved.

### 3. Passive-aggressiveness meter — `vibe_check.py` (Score) — the joyful one

10 real-life-flavored notes and messages ("Thanks so much for *finally* taking out the
trash!!", "Per my last email...") scored on a 4-level escalation rubric — good / warning
/ serious / critical — from a plain, sincere statement to full passive-aggressive
weaponry. Uses `Score` instead of `Noul` because "how passive-aggressive is this" is a
matter of degree, not yes/no; the rubric deliberately reuses good/warning/serious/critical
because this genuinely is a state escalation, not an arbitrary 0–4 scale.

```bash
python vibe_check.py
```

Prints each note ranked worst-to-best with its score, confidence, and level label, then
crowns the most passive-aggressive one.

**What we found:** the model correctly ranked the sarcastic "so thoughtful of you" note
highest (2.95/3, 0.95 confidence) and the sincere performance-review comment lowest
(0.14/3), and — nicely — showed *lower* confidence on genuinely ambiguous cases like a
"no worries :)" message where even a person would be unsure if it's sincere or pointed.
