# Potpie Docs Parser

Ask the [Potpie docs](https://docs.potpie.ai) a question, get back the **exact
paragraph that answers it** — never generated prose. If the docs don't cover it,
the app says so instead of guessing.

The search is powered only by [Jev](https://docs.typesafe.ai/models), a TypeSafe
System One model. **Jev is the engine; the Potpie docs are the corpus.** No LLM,
no embeddings, no vector database — nothing in this repo can write a sentence.

## How it works

```
query → BM25 shortlist (stdlib, top 30 of 349 blocks)
      → ONE system_one call:  Choice where   (which block answers?)
                              Noul  exists   (is it in the docs at all?)
                              Noul  fully    (does one block state it outright?)
                              Choice router  (which page covers this?)
      → verdict: answered (fully ≥ 0.70) / partial / not in this document (exists < 0.30)
      → render the winning block verbatim + heading breadcrumb + probabilities
```

Every answer is a byte-for-byte copy of a docs block. The model only ranks and
judges; it never writes.

## Commands

Typed into the chat box; handled locally, so an unknown one costs no Jev call.

| Command | What |
|---|---|
| `/help` | list the commands |
| `/clear` | wipe the thread and its saved copy |
| `/health` | check the docs server is up (useful mid-demo) |

Typing `/` opens a filtered palette above the composer: ↑/↓ to move, Enter or
Tab to run, Esc to dismiss.

## Layout

| Path | What |
|---|---|
| `api/index.py` | FastAPI app — `POST /api/ask`, `GET /api/health`. Vercel entrypoint. |
| `backend/search/jev_search.py` | BM25 index + the single Jev call + verdict thresholds |
| `backend/search/eval.py` | Gold-set eval (33 queries) and the no-LLM audit |
| `backend/corpus/build_corpus.py` | Fetches `llms.txt` → every page `.md` → `corpus.json` |
| `public/` | The UI — vanilla JS, no build step, no dependencies |
| `public/potpie-mark.png` | Potpie's own mark, used as logo and favicon |

## Run locally

```bash
pip install -r requirements.txt
export TYPESAFE_API_KEY=...          # the Jev key; see .env.example
uvicorn api.index:app --port 8123    # serves the API *and* public/
open http://127.0.0.1:8123
```

The UI calls the API same-origin, so there is nothing else to start.

## Deploy to Vercel

```bash
vercel                                        # link the project
vercel env add TYPESAFE_API_KEY production    # server-side only
vercel --prod
```

`vercel.json` routes `/api/*` to the Python function and serves `public/`
statically. The API key is read from the environment server-side and is never
sent to the browser.

## Feedback loop

Each answer carries 👍/👎. A thumbs-down asks *what* went wrong — wrong section,
not in the docs, wrong verdict, incomplete — and the rating is stored **with the
scores that produced it**, because a bare thumb is noise but a disputed verdict
next to its `exists` value is a candidate gold row.

```bash
POST /api/feedback        # appended to backend/feedback.jsonl, one JSON per line
python3 backend/search/eval.py --feedback    # group disputes into tuning work
```

`--feedback` keeps the last rating per answer and groups the down-votes by
reason, because each reason points at a different fix:

| reason | what it means |
|---|---|
| `not-in-docs` | abstention missed — `exists` was too high |
| `wrong-verdict` | threshold candidate — check `exists`/`fully` against the band |
| `wrong-section` | retrieval miss — that block should not have ranked first |
| `incomplete` | a genuine partial the gold set probably lacks |

The log is gitignored: it holds whatever users typed. **On Vercel the filesystem
is ephemeral**, so ratings survive only within a warm instance — point
`FEEDBACK_PATH` at a real store (Vercel KV, Postgres, S3) before relying on it
in production.

## Verify

```bash
python3 backend/search/build_gold.py                         # regenerate the gold set from the corpus
python3 backend/search/eval.py --local-only                  # BM25 recall + no-LLM audit, 0 API calls
TYPESAFE_API_KEY=... python3 backend/search/eval.py --live   # 198 calls (~$0.14), verdict accuracy
python3 backend/corpus/build_corpus.py --check               # rebuild + validate the corpus
```

### The gold set

198 queries, regenerated by `build_gold.py` so it cannot rot when the docs
change. The set deliberately grades different claims at different strengths,
because they are not equally verifiable:

| what is measured | n | how the label is justified |
|---|---|---|
| retrieval rank | 145 | the cited block's heading names the question's subject |
| abstention | 49 | the question's key noun appears **nowhere** in the corpus |
| verdict (answered) | 16 | the block visibly *defines* the subject, or carries real steps/code |
| verdict (partial) | 4 | hand-curated, evidence re-checked at build time |

**Why 129 of the answerables are graded on rank only.** Auto-generating a
question from a heading proves the block is the right one to *retrieve*. It
does not prove the block "directly states the answer" — and that judgement is
exactly what `fully` is under test to make. Asserting it by regex would just
be a worse copy of the model being evaluated, so where the evidence is thin
the row scores retrieval and stays out of the verdict number.

This was learned the hard way: an earlier version labelled all 145 as
"answered" and scored 86.9%. Inspection showed the model was right and the
labels were wrong — `examples/null-pointer` walks through *tracing* a null
pointer and never defines the term, so "What is Null Pointer?" has no answer
in the docs to find.

Questions are template-derived from headings, so phrasing is uniform rather
than natural, and a sample was read by hand rather than every row.

`eval.py` exits nonzero if either goal is missed, if BM25 recall drops below its
floor, or if any Python file imports an LLM library — that audit is what keeps
the "no LLM" claim honest.

Local BM25 recall is **144/145**. The one miss, *"How do I install Potpie?"*, is
a real ambiguity — CLI install versus self-hosted install — and is kept on
purpose. A benchmark that scores 100% has stopped discriminating: it can no
longer tell you whether your next change helped or hurt.

`--live --save rows.json` dumps the raw `exists`/`fully` scores so thresholds can
be swept offline without spending API calls.

## Notes

- **Scores vary run to run.** Three sweeps of the same 33 queries scored 29, 31
  and 33 of 33 before tuning. Queries near a threshold can flip verdict between
  runs, so treat a single sweep as a sample, not a guarantee.
- **`ABSENT` is 0.30, not 0.35.** Two genuine partials scored 0.31/0.34 and
  flipped between runs. Unanswerable queries score ~0.02, so abstention keeps a
  0.28 margin. `FOUND` is deliberately held at 0.70: a sweep showed 0.50 scoring
  one query higher, but a "half-states it" bar is the false confidence this tool
  exists to avoid.
- **Terse keyword queries tend to read as `partial`.** "self hosting local setup"
  has no question for `fully` to resolve, and the answer genuinely spans eight
  blocks. The right block still ranks first; only the badge is conservative.
- Build-time filter drops text repeated on more than half the pages (the Mintlify
  doc-index banner was 46 identical blocks, 12% of the corpus).
- The corpus is committed (`backend/corpus/corpus.json`, 349 blocks / 46 pages)
  so deploys need no build step or network fetch.
- Docs blocks are rendered as Markdown by a ~90-line renderer in `app.js` —
  no library, because the UI ships zero dependencies. Input is HTML-escaped
  *before* parsing, so only the small tag set the renderer builds itself can
  reach the DOM, and only `https://` links ever become an `href`.
- Rendering adds and removes no words. Potpie's docs embed raw HTML/JSX, so
  `<img>` becomes a real figure, `<a href>` a real link, and the `title=`/`body=`
  text on `<Step>`, `<Accordion>`, `<Card>` and `<ParamField>` is kept. Only
  wrappers that carry no words (`<Steps>`, `<CardGroup>`, …) are dropped.
  **Copy quote** still copies the raw source, so the claim stays checkable.
- Images load from Potpie's CDN. If one is blocked or missing it is replaced by
  its alt text rather than a broken-image icon — via a JS listener plus a
  timeout, since a blocked image can fail without firing `error`.
- The accent (`#B6E343`) and ground (`#022D2C`) are sampled from Potpie's own
  mark, so the logo and the UI agree rather than clashing.
- This is an **unofficial** demo and says so in the footer. It uses Potpie's
  logo and name because it searches Potpie's docs; it is not affiliated with
  Potpie and does not present itself as an official product.
- `Source` links go to the rendered docs page with a section anchor, not the
  `.md` file the ingester fetches — `doc_link()` in `api/index.py` does that
  conversion once, so every client gets a human-readable URL.
- Images and video in the docs are ignored: Jev is text-only.
- The hero's "0% generated" line is an architectural claim, not a score: the
  code has no text-generation path at all, so answer text cannot be invented.
  The eval figures beside it are the latest run, not a standing guarantee —
  see the run-to-run variance note above.
