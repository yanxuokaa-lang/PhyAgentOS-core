### 具体失败场景与现有机制不足 / Concrete Failure and Existing-Mechanism Gap
- `object.place` 的 source admission 用 `object.acquire.result.new_scene_revision` 证明当前 scene，却从 `object.acquire.result.scene_revision` 编译 place 参数；在 provider 不二次修正 scene 的实现中，合法抓取后的放置会携带旧 scene。现有 scene-relation gate 只验证 source 是否可用，未验证每个映射字段语义，普通类型检查无法区分两个合法字符串。 / Source admission proves the current scene with `object.acquire.result.new_scene_revision` but compiles the place argument from `object.acquire.result.scene_revision`; an Adapter that does not independently replace the scene would admit placement with the stale scene after a valid acquisition. The existing scene-relation gate validates source eligibility, not the semantics of every mapped string, and ordinary type checks cannot distinguish two valid strings.
- place projection 依赖 Persistent Runtime 私有添加的 `result.new_scene_revision` 与 `result.acquire_invocation_ref`；基础 acquire output schema 设置 `additionalProperties: false` 却没有这些字段。当前 Core 测试手工构造了超出公开 schema 的响应，因此掩盖了跨 Adapter 不兼容。 / The place projection depends on `result.new_scene_revision` and `result.acquire_invocation_ref` privately added by the Persistent Runtime while the base acquire output schema has `additionalProperties: false` and declares neither. The current Core test handcrafts an over-schema response and therefore masks cross-Adapter incompatibility.
- 投影 DSL 允许 `scene_relation=predecessor_effect` 与 `source_scope=evidence` 组合，也允许仅填写 `unique_item_join_field`；这些配置能够通过模型校验但不具备一致可执行语义。Git、版本号、主键、事务、唯一约束与普通 Tool 单测均不会在 ToolSpec 加载时拒绝这类结构错误，因此需要在现有 Pydantic contract validator 中补充局部一致性约束，而不新增 hash、冻结 contract 或平行 gate。 / The projection DSL permits `scene_relation=predecessor_effect` with `source_scope=evidence` and permits a standalone `unique_item_join_field`; these configurations pass model validation without coherent execution semantics. Git, versions, primary keys, transactions, uniqueness constraints, and ordinary Tool tests do not reject such structural errors at ToolSpec load time, so the existing Pydantic contract validator needs local consistency checks rather than a new hash, frozen contract, or parallel gate.
