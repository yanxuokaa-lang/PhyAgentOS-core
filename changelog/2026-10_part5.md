### 具体失败场景与现有机制不足 / Concrete Failure Scenario and Existing-Gap Analysis
- `red_acquire` 已实际执行 910 simulator steps；红块在接触/闭合后位移，但 lift 验证时仍与桌面接触且抬升不足 1 cm。Runtime 权威回执为 `status=unknown`、`world_change_started=true`、`outcome_known=false`、`retryable_in_revision=false`、`requires_replan=true`、`recommended_action=reconcile_world`。原 revision 的观测、几何、候选和 preparation 已失效，直接重试会在未知世界状态上重复物理 Action。
- `AgentRecoveryDecisions.select_recovery()` 已确定性选择 `replan`，但 `propose_replan()` 仍要求模型恰好返回一个包含完整 `nodes` 的 `submit_recovery` Tool Call。该调用没有返回唯一结构化结果，抛出 `ValueError: recovery model returned no unique decision`，使任务停在 `awaiting_replan`；这把必要的第一步场景对账错误地依赖于模型输出格式。
- Git、版本号、主键、事务、类型和普通重试只能保护记录一致性，不能从已失效场景中恢复当前实体位置；需要的是已有 ToolSpec `refreshes_scene` 元数据驱动的窄恢复语义。该机制不新增 hash、发布 gate 或运动旁路，且只在 Runtime 已明确声明世界改变且需要 replan 时启用。

### 架构与安全边界 / Architecture and Safety Boundaries
- Core 不命名 `scene.observe`、摄像头、颜色、RGB、排列或具体 provider；只消费冻结 ToolSpec 的 `semantics=query`、`refreshes_scene=true`、capability 与绑定要求。
- Bootstrap graph 只建立新 Query 义务，不执行 Tool、不生成传感器参数、不推断实体状态、不创建 Action；具体 Query 仍由 AgentLoop 的正常 selection/execution 路径处理。
- 未知 Action 仍不可 replay 或原 revision retry；任何后续 Action 必须经新场景证据、理解/绑定、prepare、Gateway admission 和 terminal settlement。
- 若没有唯一且可空绑定的 scene-refresh capability，保持现有模型提议；模型仍失败时继续 `awaiting_replan`，不得猜测 Tool 或参数。
