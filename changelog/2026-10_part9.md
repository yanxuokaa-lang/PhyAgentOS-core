### 具体失败场景与现有机制不足 / Failure Scenarios and Existing Gaps
- The LabUtopia composition disables legacy Action registration, while `RuntimeSubtaskDriver` starts internal Action Tool IDs through the Runtime registry. This prevents the composite task from reaching acquire/place even when the outer subtask Action is registered; Agent-facing plan filtering alone does not register internal Runtime endpoints.
- The standard preparation provider delegates to an engine `prepare_manipulation` port that the current engine does not implement. A valid profile or old cycle preparation cannot prove measured-target route qualification and cannot provide the durable assignment consumed by acquire/place.
- Fake camera/provider fixtures prove contracts only. They cannot establish that a live Isaac camera session, sensor calibration, model inference, or scene revision is available in the current runtime process.
- No live motion begins until the full no-motion Runtime path, frame/calibration lineage, route qualification, workspace/collision checks, stop path, and explicit simulation capability are verified. Missing prerequisites must remain unavailable rather than falling back to cycle/profile targets.

### 验证边界 / Validation Boundary
- First validate provider-neutral contracts and Runtime lifecycle with no-motion tests. Then validate the real observation and provider process only if the Isaac camera session is active and its live metadata/artifact path is available. Finally attempt the requested single simulation task only if adapter preparation supplies a measured route and explicit safety checks pass.
- A blocked external prerequisite does not turn the phase into a pass. No hardware execution is in scope.
