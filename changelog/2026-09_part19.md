### 失败场景依据 / Failure scenario
三次独立 GraspNet AgentTask 均将 32 个真实候选送入 `manipulation.prepare`，随后在路线规划启动前返回 `preparation_provider_error`。对应 preparation metrics 精确记录 `CuroboWorldPortError: observed support geometry is unavailable`。当前 Grounding 仅从 understanding 的 `on/is_on` 关系解析支撑对象；实时模型对 RGB 三块只返回 `right_of/above` 关系，因此支撑面为 None，adapter 将其正确视为未知并拒绝规划。现有仿真 table fallback 被 observed profile 明确禁止，重试模型或重生抓取候选不会产生缺失的几何事实。需要从同一观测深度与对象分割 mask 得到传感器拥有的支撑几何；若证据不足仍 fail closed。
- Three independent GraspNet AgentTasks each sent 32 real candidates to `manipulation.prepare`, then returned `preparation_provider_error` before route planning. Preparation metrics identify `CuroboWorldPortError: observed support geometry is unavailable`. Grounding currently resolves support only through `on/is_on` understanding relations; live RGB-block understanding returned only `right_of/above`, leaving support as None, which the adapter correctly treats as unknown and rejects. The observed profile forbids simulator table fallback, and retrying the model or regenerating grasp candidates cannot produce the missing geometry. Sensor-owned support geometry must be derived from the same observation depth and object segmentation masks, while insufficient evidence remains fail-closed.
