### 七维复审 / Seven-Dimension Review
1. 架构所有权：planner 扩展只生成内存选项；AgentLoop 负责编排；ToolRegistry/wrapper、compiler、Coordinator 继续分别拥有调用、编译与 revision 持久化，无第二 scheduler、状态库、loader 或执行器。 / Architecture: the planner extension only proposes in-memory options; AgentLoop orchestrates; ToolRegistry/wrapper, compiler, and Coordinator retain invocation, compilation, and revision persistence ownership, with no second scheduler, store, loader, or executor.
2. 正确性与事实完整性：选项义务必须与节点义务完全一致；task/revision/scene、当前 evidence 和完成态在消费前后复核；节点仍由原 compiler 校验 capability、binding、dependency 和证据。 / Correctness and fact completeness: option obligations exactly match node obligations; task/revision/scene, current evidence, and completion state are rechecked around consumption; the existing compiler still validates capabilities, bindings, dependencies, and evidence.
3. 错误与状态可观测性：插件异常、歧义、无效选项、旧身份和 wrapper 拒绝产生具体 fallback 原因；成功结果同时要求 `ok:true` 与 revision 前进，禁止伪成功。 / Error and state observability: provider errors, ambiguity, invalid options, stale identity, and wrapper rejection produce precise fallback reasons; success requires both `ok:true` and revision advancement, preventing fake success.
4. 恢复、幂等与执行对账：插件不持久化 selection/执行；旧 revision 返回立即交还宿主，Tool 拒绝不创建 revision；原 continuation 原子检查与 Action/Session nonterminal 对账保持不变。 / Recovery, idempotency, and reconciliation: the plugin persists no selection or execution; stale revision responses return control to the host, Tool rejection creates no revision, and existing atomic continuation and nonterminal Action/Session reconciliation remain unchanged.
5. 机器人与 no-motion 安全：方法接受只声明 PlanNode，不执行节点或授权运动；仍需后续 selection、Gateway admission、settlement 和 Verifier；未调用 Runtime、Gateway、相机、仿真或机械臂。 / Robotics and no-motion safety: accepting a method only declares PlanNodes and neither executes nor authorizes motion; later selection, Gateway admission, settlement, and Verifier remain required; no Runtime, Gateway, camera, simulation, or robot was invoked.
6. 扩展兼容性：旧 `PlannerPlugin` 必需方法不变；缺少可选方法、空结果和多选均走原 LLM；`PlanningRequest.scene_revision` 有兼容默认值，Core 不导入具体 Skill/JEV 实现。 / Extension compatibility: required `PlannerPlugin` methods are unchanged; missing capability, empty results, and multiple options retain the LLM path; `PlanningRequest.scene_revision` has a compatible default and Core imports no concrete Skill/JEV implementation.
7. AgentLoop 收敛、调用次数与预算：唯一选项 provider/LLM=0、continuation Tool=1；fallback LLM=1；正常续段 `counts_toward_replan_budget=False`，无执行重放或额外认知回合。 / AgentLoop convergence, calls, and budget: one option yields provider/LLM=0 and continuation Tool=1; fallback uses LLM=1; normal continuation keeps `counts_toward_replan_budget=False`, with no execution replay or extra cognition turn.
