### 失败场景与现有机制不足 / Failure Scenario and Existing Gap
- 失败场景：宿主若把静态 profile 中的 `calibration_ref` 当作当前相机校准，传感器移动或分辨率/镜头变化后，测量数据会被错误投影到旧 frame。当前 `IsaacCameraObservationSource` 只接受 opaque calibration reference，类型检查和普通测试无法证明该 reference 对应活动相机的内外参；因此从活动相机读取并持久化真实校准数据。 / Failure scenario: if the host reuses a static profile `calibration_ref` after a sensor pose, resolution, or lens change, measurements may be projected using stale calibration. The current source accepts only an opaque calibration reference, and types/ordinary tests cannot establish that it describes the active camera; therefore persist measured intrinsics/extrinsics from the active camera.
- 本阶段不解决相机句柄跨进程问题：当前 Isaac action worker 每回合创建/关闭 SimulationApp，PAOS host 不持有该进程的 camera handles；metadata provider 必须在已有 session 所属进程内构造，不能单独证明 observation/action 使用同一 scene revision。 / This stage does not solve cross-process camera-handle sharing: the Isaac action worker creates/closes SimulationApp per episode, and the PAOS host does not own its camera handles; the provider must be constructed in the owning live-session process and does not alone prove observation/action share a scene revision.
