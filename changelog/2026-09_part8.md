Qwen provider 不可用、模型目录不完整、worker 超时或输出非 JSON 时，`scene.understand` 必须返回有界 provider failure；不得回退到 simulator truth、旧场景证据或伪造语义结果。Qwen、LocateAnything 与 SAM2 仍按顺序 worker 生命周期运行，以适配 16GB 显存。

When the Qwen provider is unavailable, the model directory is incomplete, the worker times out, or output is not JSON, `scene.understand` must expose a bounded provider failure; it must not fall back to simulator truth, stale evidence, or fabricated semantics. Qwen, LocateAnything, and SAM2 retain sequential worker lifetimes for the 16GB GPU.

### 失败场景 / Failure Scenario

当前 robotwin-persistent profile 依赖大量交互式 shell exports；新环境遗漏任一变量时只能在启动时逐项失败。与此同时，preflight 只读取 `os.environ`，实际 Dora 启动却另行覆盖 `profile.environment`，造成校验输入与执行输入不一致。自包含 Node 已把 adapter root 绑定到其嵌入 payload，但 Skill 仍要求操作员提供源码树路径，导致发布制品无法真正脱离仓库启动。

The robotwin-persistent profile currently depends on many interactive shell exports, so a clean host fails incrementally when any value is omitted. Preflight reads only `os.environ` while Dora launch separately overlays `profile.environment`, so validation and execution do not use the same input. The self-contained Node already binds its adapter root to the embedded payload, yet the Skill still requires an operator-supplied source-tree path, preventing repository-independent startup.

### 防御机制边界 / Defensive Mechanism Boundary

本次不新增 hash、baseline、冻结 contract 或运动 gate。环境文件只在现有 Runtime 启动这一跨进程部署边界执行普通语法、重复键与必需变量校验；既有 Gateway readiness、planning binding、Action admission、frame/calibration 和 verifier 门禁保持不变。

This change adds no hash, baseline, frozen contract, or motion gate. The environment file receives ordinary syntax, duplicate-key, and required-variable validation only at the existing cross-process Runtime startup boundary; existing Gateway readiness, planning binding, Action admission, frame/calibration, and verifier gates remain unchanged.
